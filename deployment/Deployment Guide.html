Architecture

How a form submission flows

1
Visitor fills the form on quantach.com (GitHub Pages)

The HTML page makes a fetch() POST request to your Azure Function URL with the form data as JSON.

2
Azure Function validates the input

Checks that first name, last name, email, and phone are present and valid. Returns a 422 error with a user-friendly message if not.

3
Submission saved to Azure Blob Storage

A JSON file is written to form-submissions/YYYY-MM-DD/HH-MM-SS_LastName.json. You can browse submissions in the Azure Portal at any time.

4
Email alert sent via SendGrid

A branded HTML email with all submission details — and a one-click Reply button — is sent to info@quantach.com.

Step 2

Azure Setup

Create the Resource Group, Storage Account, and Function App in Azure. Run these commands in your terminal.

1. Set your variables

# Choose names — must be globally unique for storage + function app
RESOURCE_GROUP="quanta-rg"
LOCATION="canadacentral"
STORAGE_ACCOUNT="quantaforms"        # lowercase, no hyphens, max 24 chars
FUNCTION_APP="quanta-form-handler"   # your function app name
CONTAINER_NAME="form-submissions"

2. Create Resource Group

az group create \
  --name $RESOURCE_GROUP \
  --location $LOCATION

3. Create Storage Account

az storage account create \
  --name $STORAGE_ACCOUNT \
  --resource-group $RESOURCE_GROUP \
  --location $LOCATION \
  --sku Standard_LRS \
  --kind StorageV2

4. Create the Blob container

az storage container create \
  --name $CONTAINER_NAME \
  --account-name $STORAGE_ACCOUNT \
  --auth-mode login

5. Create the Function App

az functionapp create \
  --resource-group $RESOURCE_GROUP \
  --consumption-plan-location $LOCATION \
  --runtime dotnet-isolated \
  --runtime-version 10 \
  --functions-version 4 \
  --name $FUNCTION_APP \
  --storage-account $STORAGE_ACCOUNT \
  --os-type Linux
✓ CheckpointYou should now see the Function App in your Azure Portal under the resource group quanta-rg.
Step 3

Deploy the Function

Build and publish the .NET 10 Azure Function from the deployment/azure-function/ folder in your project.

1. Navigate to the function folder

cd deployment/azure-function

2. Test locally (optional but recommended)

# Make sure Azurite (local storage emulator) is running, or use a real connection string
func start

The function will be available at http://localhost:7071/api/submit. Test it with curl:

curl -X POST http://localhost:7071/api/submit \
  -H "Content-Type: application/json" \
  -d '{"firstName":"Jane","lastName":"Smith","email":"jane@test.com","phone":"+14165550100","message":"Test"}'

3. Publish to Azure

func azure functionapp publish quanta-form-handler --dotnet-isolated

4. Set environment variables in Azure

az functionapp config appsettings set \
  --name quanta-form-handler \
  --resource-group quanta-rg \
  --settings \
    "BlobContainerName=form-submissions" \
    "SendGridApiKey=SG.YOUR_KEY_HERE" \
    "AlertEmailTo=info@quantach.com" \
    "AlertEmailFrom=noreply@quantach.com" \
    "AllowedOrigin=https://YOUR_GITHUB_USERNAME.github.io"

5. Get your Function URL

az functionapp function show \
  --name quanta-form-handler \
  --resource-group quanta-rg \
  --function-name SubmitForm \
  --query "invokeUrlTemplate" -o tsv

Copy this URL — you'll paste it into the website's FORM_ENDPOINT constant in the next step.

Update the websiteOpen ui_kits/website/index.html and replace the placeholder in the FORM_ENDPOINT constant at the top of the <script> block with your real Azure Function URL.
Step 4

SendGrid Email Alerts

SendGrid's free tier sends up to 100 emails/day — more than enough. Setup takes about 10 minutes.

1
Create a SendGrid account

Go to sendgrid.com → Sign up for the free plan. Verify your email.

2
Create an API Key

In SendGrid: Settings → API Keys → Create API Key → choose Restricted Access → enable Mail Send → Create. Copy the key immediately (shown once).

3
Verify your sender email

Settings → Sender Authentication → Single Sender Verification → add noreply@quantach.com (or any email you control). Verify via the email SendGrid sends you.

4
Add the API key to Azure
az functionapp config appsettings set \
  --name quanta-form-handler \
  --resource-group quanta-rg \
  --settings "SendGridApiKey=SG.YOUR_ACTUAL_KEY"
What the email looks likeEach submission triggers a branded HTML email with the sender's name, email (clickable), phone, company, industry, and message — plus a one-click "Reply to [Name]" button. See SubmitFormFunction.cs → BuildEmailHtml() to customise the template.

Step 6

Custom Domain

Point quantach.com to your GitHub Pages site. Takes ~10 minutes + up to 24h DNS propagation.

1
Add a CNAME file to your repo

Create a file named exactly CNAME (no extension) in your repo root with one line:

quantach.com
2
Add DNS records at your registrar

Log into your domain registrar (GoDaddy, Namecheap, etc.) and add these records:

# For root domain (quantach.com) — add 4 A records:
A    @    185.199.108.153
A    @    185.199.109.153
A    @    185.199.110.153
A    @    185.199.111.153

# For www subdomain — add 1 CNAME:
CNAME    www    YOUR_USERNAME.github.io
3
Configure in GitHub

In your repo: Settings → Pages → Custom domain → enter quantach.com → Save. Check Enforce HTTPS once DNS propagates (GitHub provides a free SSL certificate via Let's Encrypt).

4
Update AllowedOrigin in Azure

Once your domain is live, update the CORS setting so the Azure Function only accepts requests from your real domain:

az functionapp config appsettings set \
  --name quanta-form-handler \
  --resource-group quanta-rg \
  --settings "AllowedOrigin=https://quantach.com"
Reference

Environment Variables

All configuration for the Azure Function lives in App Settings (environment variables). Set them via the Azure CLI commands shown in Step 3, or through the Azure Portal.

VariableDescriptionExample
AzureWebJobsStorage Connection string for the Azure Storage Account. Set automatically when you create the Function App linked to a storage account. DefaultEndpointsProtocol=https;AccountName=…
BlobContainerName Name of the blob container where submissions are saved. Defaults to form-submissions. form-submissions
SendGridApiKey Your SendGrid API key. If omitted, email alerts are skipped (submissions still save to blob). SG.xxxxxxxxxxxx
AlertEmailTo Email address that receives the alert. Defaults to info@quantach.com. info@quantach.com
AlertEmailFrom Verified SendGrid sender address. Must be verified in SendGrid. noreply@quantach.com
AllowedOrigin CORS allowed origin. Set to your domain in production. Defaults to * (any origin). https://quantach.com

* Required fields.

Never commit secrets to GitThe local.settings.json file is already listed in .gitignore by Azure Functions tooling. Never commit API keys or connection strings to your repository.
